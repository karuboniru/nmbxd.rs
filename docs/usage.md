# 使用说明与功能细节

[返回 README](../README.md) · [技术说明](technical.md)

## 设置

主题按钮循环切换跟随系统、浅色和深色，首次启动跟随系统，选择会保存到配置目录的 `appearance.json`。

标题栏“设置”可导入和选择认证饼干、修改订阅 ID、网页地址、界面字体，以及 UI / 串列表 / 正文三个独立字号（默认 16 / 14 / 14 px；编辑框正文跟随正文字号）。保存后即时生效，重启后保留。网页地址默认 `https://www.nmbxd1.com/`，也可输入 `www.nmbxd1.com`；只接受 HTTPS 站点根地址，用于发串 / 回复，JSON 浏览 API 的地址独立。旧设置会自动采用新默认值。在网页版饼干二维码上右键选择“复制图像链接”，将 `https://publicapi.ovear.info/qrcode.php?...&text=...&base64=1` 粘贴到设置中导入，无需 F12。HTTP 和 HTTPS 链接均支持，链接中的 Base64 JSON 在本地解析，可连续导入多个饼干。选择认证饼干后用于浏览；选择游客并保存后匿名请求，不会重新采用 `.env` 中的旧 cookie。字体下拉框列出系统安装的字体，支持搜索和预览；保存后应用到整个界面，包括编辑器，切换主题仍保留字体选择。

每个饼干旁的“删除”按钮会将其标为待删除，以灰色虚线保留在列表中，按钮变为“恢复”，保存前可撤销删除。点击“保存”后才删除本地文件；关闭设置而不保存会撤回所有改动。删除当前认证饼干会选择游客，可在保存前改选其他饼干。回复框曾选择的饼干被删除后，将回退到该串仍可用的记录或当前认证饼干；没有可用选择时需要先选择或导入饼干。

设置保存在配置目录的 `settings.json`：Linux 默认 `~/.config/rdnmb/settings.json`，Windows 默认 `%APPDATA%\rdnmb\settings.json`，也支持绝对路径的 `XDG_CONFIG_HOME` 覆盖基础目录。保存的设置优先于启动环境和 `.env`。启动时会自动将旧 `nmbxd/settings.json` 复制到新目录，保留 cookie、订阅 ID、字体和字号；新目录没有 `appearance.json` 时先读取旧目录中的主题，下次保存主题时写入新目录。已有新目录文件时优先使用新文件，旧文件仍保留。Linux 文件权限为 `0600`，使用临时文件原子替换。饼干原文单独保存在配置目录的 `cookie/${name}.cookie`；旧 cookie 自动迁移为 `default.cookie`，已有同名文件不会覆盖，发生冲突时旧值另存。`settings.json` 仅记录认证饼干名称。饼干是本地明文保存，不是密钥环存储；分发包绝不包含这些文件。保存先检查 cookie 格式，再替换网络客户端；服务器是否接受该饼干以实际请求为准。不会通过发帖验证饼干。

## 阅读与引用树

第二栏顶部“刷新”重新请求当前板块第一页，检查最新串；不会关闭正在阅读的串或清空编辑器草稿。

- 首次打开串读取第一页，再次打开则恢复保存的阅读位置并优先读取本地缓存。阅读区顶部显示当前页 / 总页数，可向前、向后加载或输入页码跳转，不必滚动到末尾。
- 跳页成功后，以目标页作为新的已加载子集；失败则保留原内容。时间顺序连续显示已加载子集中的所有回复；新页接在后面并保持当前滚动位置，切换引用树则按引用关系聚合这个子集。树模式可手动向前 / 向后各加载一页 buffer，并显示已加载页范围；不追踪引用抓取，也没有自动轮询。
- 串列表与回复区向下滚到底时自动加载一页；引用树向已加载范围后方扩展。分页由用户滚动触发，不因窗口变大或短页内容自动连续抓取。每次浏览一个串，首次滑到末尾时自动联网检查一次新回复；从缓存打开后不足一屏也立即检查一次。两种触发共享一次额度，切换到其他串再回来会重置。失败后停止自动重试，显示手动重试。
- “已到底”仍可点击“刷新，检查新回复”：重新请求已加载范围的末页，更新总页数且保留当前子集；有新页后可以继续加载。板块末尾也可重新检查下一页。
- HTTP 在独立线程串行执行，请求结束后间隔至少 800ms；页加载按钮有进行中保护。串页同时保存在内存和本地 SQLite 中，已缓存页面无需再次请求；首次到达末尾的自动检查、明确刷新和清缓存重载会联网。
- 切换“时间顺序 / 引用树”不产生网络请求。引用树从正文提取 `>>No.123` / `>>123`，保留多个引用，选择第一个已知且不会成环的引用作为父节点；其他回复归到主串下。
- 未加载 / 串外引用明确标注；不会假装已知其属于当前串。新页面加载后重新组织树，去重并阻止循环引用。分支可折叠，视觉缩进最多七层。
- “刷新”成功后重新从第一页建立子集，适用于读取新回复或核实发送结果；失败则保留原内容。

## 图片与 emoji

帖子与串列表显示图片缩略图，点击正文图片可在客户端查看原图；图片失败可点击重试。只有进入可视区域的图片才排队加载，原图需主动点击。图片请求不带饼干，不跟随重定向；限制并发、下载大小和解码像素数，使用有上限的会话内存缓存及跨重启的磁盘缓存。正文中的任意 HTML 外链图片不会自动加载。

内置 Noto Color Emoji 位图字体，供 Unicode emoji 的字体回退使用，不改变选择的正文 / 编辑器字体。支持字体所包含的 emoji；新版本 Unicode 或复杂组合的显示仍取决于字体与 GPUI 的 shaping 支持。字体许可证随发行包附带。

## 发串与回复

点“发起新串”或“回复”打开编辑栏；引用回复自动插入引用号。发送目标固定显示在编辑栏标题中。草稿按主串或板块分别保留，切换目标时收起旧编辑器，再次打开对应目标可继续编辑（仅当前运行）。发送进行中禁止编辑与重复点击。

旧网页域名的跳转会导致发帖失败，请在设置中检查网页地址。遇到 3xx 会提示状态和跳转目标，但不会自动携带饼干向新站点重放 POST。

编辑栏支持一张图片附件：点击“选择图片”，或从剪贴板粘贴图片（编辑框内 Ctrl+V / macOS Cmd+V，也可点“粘贴图片”）。选中后显示预览，可移除或替换。图片可以不附正文，失败时保留文字和附件；收起编辑器也保留草稿，清空或发送成功才移除附件。

Linux 文件选择直接使用 XDG Desktop Portal（ashpd），不会静默回退到外部选择器；需要运行 `xdg-desktop-portal` 和桌面对应后端。使用 portal 授权返回的文件路径，兼容后续 Flatpak 文档门户；当前发布包还不是 Flatpak。非 Linux 使用 rfd 原生选择器，Windows/macOS 尚未实机验证。

上传支持 JPEG / PNG / GIF，客户端限制 10 MiB，并对图片解码尺寸设限；服务器可能有更严格限制。文件上传保留原始内容，GIF 附件保留动画（客户端预览仍为首帧）；其他剪贴板位图格式转换为 PNG。只在点击发送时上传，选择 / 粘贴不会发送内容。

点击“发送”会真实提交。成功必须由服务器明确返回成功标记；网络错误或不明返回保留草稿，且不会自动重试。请先刷新确认，避免重复发帖。

## 引用预览与外部链接

正文中的 `>>No.123`、`>>123`、`No.123` 和岛内串链接可点击预览；预览内的引用可以继续打开，支持逐层返回和关闭全部。循环引用返回已打开的层级，最多嵌套 32 层。已加载的消息直接复用，不主动预取引用或扫描页面。

“跳转到串”打开对应主串；已确认属于当前串的消息显示“已在当前串”，点击完全不改变阅读页码、位置和草稿。引用 API 不提供所属主串编号：未知引用只在点击跳转时尝试确认其是否为主串；串外回复不能定位时会明确提示，仍可阅读预览。

HTTP(S) 外链通过系统默认浏览器打开，保留 HTML 链接的目标地址；拒绝 javascript / data / file 等协议。

原图和引用预览支持 **Esc** 或鼠标后退键关闭；嵌套引用每次只返回一层，其他页面不拦截这些按键。

## 服务器订阅 / 收藏夹

- 左侧“☆ 我的订阅”读取岛上的订阅列表，支持刷新、滚动分页及失败后手动重试。
- 阅读区工具栏“☆ 添加订阅”收藏当前主串；已知订阅显示“已订阅 · 移除”。订阅列表每项有“移除订阅”，也可右键菜单操作。移除后保留当前阅读内容与草稿。
- 设置中的订阅 ID 默认生成随机 UUID v4，首次运行和旧配置迁移时即保存；重启不会变。不同设备填写相同 ID 可共享。切换 ID 不删除原订阅。
- **知道订阅 ID 的人可以查看和修改这份订阅**，请妥善保存；它独立于 cookie，使用订阅不需要发帖饼干。
- API 没有单串订阅状态查询；仅使用已加载订阅页和本次成功操作判断“已订阅”，不为了检查状态拉取整个收藏夹。未知状态允许直接添加，服务器重复添加不产生重复收藏。共享列表在其他设备变化后请刷新。
- 订阅读写和错误处理已用本地 HTTP 模拟服务测试，未更改真实服务器订阅；另已只读验证随机 ID 的空订阅列表。隔离 X11 会话已验证嵌套预览、Esc / 鼠标后退逐层关闭、原图 Esc 关闭和订阅设置界面。

## 复制文字、图片与另存为

- 阅读正文和引用预览可鼠标拖选，`Ctrl+C`（macOS `Cmd+C`）复制选中文字，`Ctrl+A` / `Cmd+A` 选择该条消息的全部正文；也可点“复制正文”。链接仍可点击，拖选链接文字不会打开它。
- 正文图片、引用预览图片和原图界面提供“复制图片”和“图片另存为…”。复制使用原图首帧并转换为 PNG，便于粘贴到其他应用；下载保存原始字节，保留 GIF 动画。
- 另存为先准备图片，再弹出系统保存对话框确认文件名和路径；Linux 严格使用 FileChooser portal，Windows/macOS 使用原生保存对话框。取消不写文件，现有文件不会被覆盖，请选择新名称。
- 复制/下载沿用图片来源、12 MiB 响应体、解码尺寸与并发限制，不发送 cookie，不影响发帖草稿；错误显示在状态栏。文件写入失败时会明确提示，目标文件可能不完整。

已在隔离 X11 会话实测拖选复制正文，并使用外部程序读取图片剪贴板的 PNG；原生保存对话框尚待桌面实机验证。

图片复制使用 arboard 原生剪贴板。Linux 优先使用 Wayland data-control，不支持该协议的桌面（如 GNOME）需要可用的 XWayland；失败会显示错误，可改用“图片另存为”。退出应用后图片是否保留取决于桌面剪贴板管理器。

## 发帖／回复颜文字选择器

编辑栏点击“颜文字”展开可滚动列表，选择后插入正文光标处（有选中文字时替换选区），自动收起并返回正文输入；支持撤销，Esc 可收起列表，发送中不可修改。

列表是 2026-10-23 网页快照，同时合并 [h.desktop.js](https://www.nmbxd1.com/Public/Js/h.desktop.js) 的 87 项与 [串页面 HTML](https://www.nmbxd1.com/t/69665764) 内联补丁的 12 项及 5 个命名选项，共 104 项（不含空值“无”）。保留原始顺序、换行和特殊空格；离线可用，不在每次打开选择器时请求服务器。定义与回归测试位于 `src/kaomoji.rs`。

## 独立回复草稿

回复草稿按主串号分别保留，新串草稿按板块保留（仅当前运行，不写磁盘）。切到其他串会收起旧目标编辑器；点击新目标的“回复”会打开对应草稿，文字、标题、图片与撤销历史不会从旧串带入。未完成的图片读取在切换草稿时作废，避免图片加入错误目标。编辑器标题显示回复串号，发送前再次校验当前目标；清空或发送成功只清理当前草稿。

引用回复在空草稿中直接写入 `>>No.串号`，光标落在下一行；已有正文时只补必要的分隔换行，并保留撤销历史。正文显示将 `<br>` 后用于 HTML 格式的单个源码换行视为同一次换行，不再重复生成空行；连续 `<br>` 表示的主动空行仍保留。

## 本地历史、离线缓存与连续阅读

侧栏“历史记录”提供“浏览历史 / 发串历史 / 回复历史”三个分类，按最近时间排列并可加载更多。浏览历史按串保留最近一次访问时间、摘要和阅读位置；发帖历史只记录服务器明确确认成功的发送，保存当时的标题、正文、目标和是否带图。新发串接口没有返回可确认的串号，因此这类记录展示发送内容，不猜测跳转链接；回复记录可打开目标串。

本地历史使用 SQLite，位于配置目录下的 `rdnmb/history.sqlite3`（Linux 默认 `~/.config/rdnmb/history.sqlite3`，Windows 默认 `%APPDATA%\rdnmb\history.sqlite3`，支持 `XDG_CONFIG_HOME`）。浏览记录、发帖记录和分页快照独立存储；它们会保留到下次启动。已经查看并成功加载的缩略图、原图保存在同目录的 `media-cache/`，没有查看过的图片不会提前下载。数据库不保存登录饼干。

打开浏览过的串时，优先使用本地分页快照，并恢复上次的帖子位置和偏移；已缓存的内容在断网时仍可打开。恢复时会加载阅读位置附近的连续缓存页，其余缓存按需读取。下一页直接追加到当前内容末尾，向前加载也保持当前帖子的位置；不会因自动翻页切换整个页面。输入页码并跳转属于明确重新定位。

阅读工具栏的“刷新”会重新请求首页；“清除本串缓存并重载”删除该串的分页和关联图片缓存，然后从网络重新加载，保留浏览历史及发帖历史。普通翻页优先用缓存，因此要查看服务器上的新修改，可以使用刷新或清缓存重载；串末尾“刷新，检查新回复”会重新检查末页。缓存图片保留原文件格式，界面仍只展示动画的首帧。

有图帖子的“复制图片 / 图片另存为 / 复制正文 / 引用回复”位于同一行，窄栏时可横向滚动。

右键菜单按串独立保存状态，避免多个菜单重复绘制导致 Linux 阴影叠加。首次到达串末尾或缓存内容不足一屏时自动检查新回复，每次浏览限一次，切换到其他串再回来后重置。

### 发串与回复的饼干选择

发串和回复框都有饼干下拉菜单，选择只影响本次发送，不改变浏览认证。每个串第一次回复默认使用认证饼干；成功回复后，下次回复沿用该串上次的饼干。记录只保存饼干名称，位于 `reply-cookies.json`，重启后仍有效；记录中的饼干不存在时回退到当前认证饼干。发送失败保留草稿与选择，不更新成功回复记录。
